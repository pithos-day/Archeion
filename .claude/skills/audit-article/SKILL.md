# 記事の監査

規則は編集方針 `src/content/docs/policy.md`。指摘には、根拠になる編集方針の節の名前を添える。

対象が指定されなければ、`git diff` と未コミットの変更で触った記事と論点表を対象にする。

## 1. スクリプト

```sh
pnpm check:articles
pnpm verify:citations
pnpm check
pnpm lint
```

- エラーは必ず直す。
- `check:articles` の警告は、編集方針の例外に当たるかを一件ずつ判断する。当たらなければ指摘にする。例外や誤検知なら、段落の直前に理由付きの抑制マーカーを書く案を出す (書き方は `AGENTS.md`)。
- 既にある抑制マーカーも、理由がいまの本文に合っているかを確かめる。本文を直して例外でなくなっていれば、マーカーを消す指摘にする。
- リンクの付け忘れ: `link:names` はファイルを書き換えるので、記事をスクラッチパッドにコピーし、コピーに対して実行して元と比べる。差分が出たら指摘にする。git で記事を戻さない (未コミットの編集が消える)。

  ```sh
  cp src/content/docs/articles/<slug>.mdx <スクラッチパッド>/<slug>.mdx
  pnpm link:names <スクラッチパッド>/<slug>.mdx && diff src/content/docs/articles/<slug>.mdx <スクラッチパッド>/<slug>.mdx
  ```

## 2. 論点表と本文

対象の記事の論点表のスコアと判定を表示する (コマンドは `AGENTS.md` の「コマンド」)。

- 本文が `adopted` の説で書かれているか。`alternative` と `received` の説だけが「一説には…」で書かれているか。`minor` の説が本文に残っていないか。
- 各出典が、論点の問いそのものに答えているか。周辺の事情に触れているだけの出典を数えていないか（原典は `pnpm show:sentences` で読む）。
- `narrative` と `mention` の区別が正しいか。
- `reception` に、後世に受け継がれていると判断した理由が書かれているか。
- 本文に書いた説が論点表にない、または論点表の論点が本文で触れられていない、ということがないか。

## 3. 記事をまたぐ論点

```sh
grep -rn "<論点のキーワード>" src/data/claims/   # 例: 武具 → trojan-war と odysseus
```

論点の名前は記事ごとに少し違うことがあるので、キーワードを変えて何度か探す。

同じ論点を持つほかの記事の論点表と、出典と判定が食い違っていないか。本文に書いた説が、ほかの記事で論点になっていないか。

## 4. 本文

- 同じ事実を繰り返していないか。脚注が 4 件以上ないか。脚注の出典が、古いもの、詳しいものの順に選ばれているか。
- 著者名の前置き (`check:articles` が拾わない「〜は…と伝える」などの言い方も)。
- 別名の括弧書き、装飾的な形容、筋や人物像を変えない細部。
- 表記が `names.ts` の `names` にそろっているか。「ギリシャ」、ラテン語の原典の箇所でのギリシャ名。
- 固有名詞のリンクが最初の 1 回だけか。見出し、脚注、作品名の中にリンクがないか。
- 十二の功業のような並ぶ項目に、小見出しと目的・経過・結末があるか。
- frontmatter: `created`。版なら `versionReason` の `difference` と `reception`。

## 5. 訳

脚注が引く文の訳 (`src/data/passages/`) を、原文と並べて読む。

- 原文にない内容を足していないか、落としていないか。
- 固有名詞の表記が `names.ts` と同じか。ローマ名をギリシャ名にしているか。
- 文法の解説（「双数形」など）を訳や `note` に書いていないか。
- 宗教や儀式の用語（*profanus*、*castus*、ὅσιος など）の訳語が、辞書の第一義ではなく、その場面で通る意味になっているか（例: 秘儀の場面の *profani* は「汚れた者たち」ではなく「秘儀を知らぬ者たち」）。
- 訳と本文の文だけを読んで、行動の理由が分かるか。分からなければ、きっかけの出来事が本文から落ちていないか (編集方針「行動のきっかけ」)。
- `parts` の訳が、単独でもつないでも読めるか。

## 報告

指摘を重大な順 (誤った採用説、出典の誤り → 規則違反 → 表記と文体) に、`ファイル:行` と編集方針の節を付けて並べる。修正は、依頼されたときに行い、直したら手順 1 をやり直す。
